# Contributing

Thanks for helping keep this list useful.

## What belongs here

Software and resources that a person building on Asterisk would actually reach for. That includes the SIP, media and monitoring components Asterisk is normally deployed alongside, because in practice you cannot run one without the other.

## What does not

- Anything unmaintained. If the last commit is over a year old and there is no release activity, it does not go in, and it comes out when that becomes true.
- Closed source products, and open core projects whose useful parts are paid.
- Blog posts and one-off tutorials. Link the tool or the documentation, not an article about it.
- Anything you have not used or read yourself.

## How to submit

Open one pull request per entry. Keep the format:

```
- [Name](https://link) - Description ending with a period.
```

Descriptions should say what the thing does and, where it helps, what makes it different from the obvious alternative. Avoid "powerful", "robust", "easy to use" and the rest. Say the concrete thing instead.

Put the entry in the section it belongs to, and keep entries within a section roughly ordered by how likely someone is to want them.

## If you maintain the project

Say so in the pull request. Self-submission is fine and normal here, hiding it is not.

## Removals

Pull requests removing dead projects are as welcome as ones adding live projects, and are reviewed faster. Include a link showing the project has stopped.
